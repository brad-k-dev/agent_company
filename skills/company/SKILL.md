# AI 회사 — CEO 지시 처리

CEO 지시: **$ARGUMENTS**

너는 비서실이다. 팀을 순서대로 가동하고 결과를 CEO에게 보고한다. 산출물 내용은 직접 쓰지 않는다.
배포준비팀(release)은 이 흐름에서 돌리지 않는다 — CEO가 결과를 보고 `/agent-company:release`로 직접 시작한다.

## 준비

1. 지시에서 짧은 영문 slug를 정한다(예: `memo-ios`). 작업 공간 `WS = <현재 디렉터리>/output/<slug>`.
2. `WS/brief.md`가 이미 있으면 그 안의 지시 원문을 이번 지시와 비교한다.
   - **같으면 그 WS를 그대로 쓴다** — 이어서 하기다. brief.md는 고치지 않는다.
   - 다르면 slug 뒤에 `-2`, `-3`을 붙여 비어 있는 이름을 찾는다.
3. 새 WS면 `WS/brief.md`에 CEO 지시 원문과 날짜를 적는다.

## 팀 순서

| 순서 | TEAM | NN |
|------|------|----|
| 1 | research | 01 |
| 2 | planning | 02 |
| 3 | design | 03 |
| 4 | dev | 04 |
| 5 | qa | 05 |

각 팀을 이 스킬 폴더의 `team-run.md` 절차로 가동한다. 각 팀의 `ORDER`는
"CEO 지시: <원문>. 앞 팀 산출물을 바탕으로 <팀>의 몫을 해라."
단 dev 팀은 `WS/05-qa.r1.md`가 있으면 ORDER가 "QA 반려 사항을 수정하라: <WS>/05-qa.r1.md" 다 (반려 재작업 중).

`WS/NN-<TEAM>.md`가 이미 있는 팀은 끝난 것이므로 건너뛴다 — 중간에 끊겨도 다시 실행하면 이어진다.

## 팀 사이

- 팀이 끝날 때마다 리더의 REPORT를 CEO에게 한 블록으로 보여 주고 **바로 다음 팀으로 진행한다.**
  CEO가 중간에 끼어들면 그 말을 다음 팀 ORDER에 덧붙인다.
- **QA 반려**: 판정은 `05-qa.md`의 **비어 있지 않은 마지막 줄**로만 본다. 본문 중간의
  `VERDICT: …` 언급은 판정이 아니다. 마지막 줄이 `VERDICT: FAIL` 이면:
  - `WS/05-qa.r1.md`가 **이미 있으면** 재작업을 한 번 했다는 뜻이다. **반려 재작업은 1회까지** —
    남은 결함을 안고 끝내고 CEO에게 알린다.
  - 없으면 `04-dev.md`·`04-dev/`·`05-qa.md`·`05-qa/`를 **한꺼번에** `.r1`로 옮긴 뒤 팀 순서를 다시 따른다.
    dev가 (반려 ORDER로) 다시 돌고, 이어서 QA가 다시 돈다. 넷을 먼저 옮겨 두므로 중간에 끊겨도
    다시 실행하면 같은 지점(반려 재작업 dev)에서 이어진다.

## 최종 보고

```
✅ <slug> 개발·QA 완료 — <WS>
리서치: …  / 기획: …  / 디자인: …
개발: app/ (파일 N개)  / QA: PASS|FAIL(남은 결함 N건)
다음: 배포 준비는 `/agent-company:release --project <slug>` 로 직접 시작하세요.
      (스토어 문구·빌드 설정·사용자가 할 일 목록을 만든다. 실제 업로드·심사 제출은 하지 않는다)
```
QA가 FAIL이면 "남은 결함을 먼저 고치려면 `/agent-company:team-dev`"도 함께 안내한다.
