# team-run — 한 팀을 일하게 하는 절차

너(메인 세션)는 **비서실**이다. 지시를 전달하고 결과를 나를 뿐, 산출물 내용을 직접 쓰지 않는다.
모든 판단과 작성은 각 에이전트가 한다. 에이전트 호출은 Agent 도구의 `subagent_type`으로 한다.
이 회사는 `agent-company` 플러그인이라 **에이전트 이름 앞에 `agent-company:`를 붙여 호출한다**
(예: `agent-company:dev-lead`). 리더가 돌려주는 ASSIGN/REWORK의 이름에는 접두사가 없으니 붙여서 쓴다.

## 입력

- `TEAM`: research | planning | design | dev | qa | release
- `NN`: 팀 번호 (research=01, planning=02, design=03, dev=04, qa=05, release=06)
- `WS`: 작업 공간 절대 경로 (`output/<slug>`)
- `ORDER`: 이 팀이 받은 지시

## 0. 이전 회차 보존

`<WS>/<NN>-<TEAM>.md` 나 `<WS>/<NN>-<TEAM>/` 이 이미 있으면 둘 다 `.r<N>`을 붙여 옮긴다
(`04-dev.md` → `04-dev.r1.md`, `04-dev/` → `04-dev.r1/`, N은 비어 있는 가장 작은 수).
이전 회차 파일이 이번 회차의 읽기 대상에 섞이지 않게 하기 위해서다.

**앞 팀 산출물**은 언제나 `<WS>/` 바로 아래의 `NN-<팀>.md` 파일만 뜻한다. `.r<N>`이 붙은 파일은 이전 회차라 읽지 않는다.

**앞 팀 산출물 경로는 비서실이 직접 나열해 준다** (`ls <WS>/[0-9][0-9]-*.md`에서 `.r<N>`을 뺀 것).
패턴만 주면 Glob이 없는 에이전트(예: 리서치 팀원)는 찾지 못한다.

## 1. 리더에게 지시 → 배분안 받기

`subagent_type: agent-company:<TEAM>-lead` 로 호출. 프롬프트:

```
[모드: 계획]
작업 공간: <WS>
지시: <ORDER>
먼저 읽을 것: <WS>/brief.md, <앞 팀 산출물 경로를 하나씩 나열>
팀원 작업물 폴더: <WS>/<NN>-<TEAM>/
배분안 기록: <WS>/<NN>-<TEAM>/_plan.md
```

리더 응답에서 `ASSIGN <에이전트이름>: <과제>` 줄을 모두 뽑는다. `_plan.md`가 없으면 리더에게 작성을 다시 요청한다 —
검토 단계의 리더는 새로 띄운 에이전트라 이 파일이 없으면 자기가 무엇을 배정했는지 모른다.

## 2. 팀원 병렬 실행

ASSIGN 줄마다 Agent 호출 하나(`subagent_type: agent-company:<에이전트이름>`). **한 메시지에 모두 담아 병렬로** 띄운다. 프롬프트:

```
작업 공간: <WS>
리더(<TEAM>-lead)가 배정한 과제: <과제>
참고할 파일: <WS>/<NN>-<TEAM>/_plan.md (리더의 배분·공통 이름표·인터페이스), <WS>/brief.md, <앞 팀 산출물 경로 나열>
결과 파일: <WS>/<NN>-<TEAM>/<에이전트이름>.md
```

팀원끼리 서로의 결과를 보지 않는다 — 독립된 관점을 얻기 위해서다.

## 3. 리더 검토

같은 리더를 다시 호출. 프롬프트:

```
[모드: 검토]
작업 공간: <WS>
지시: <ORDER>
네 배분안: <WS>/<NN>-<TEAM>/_plan.md
팀원 작업물: <이번에 ASSIGN한 팀원마다 <WS>/<NN>-<TEAM>/<에이전트이름>.md — 경로를 나열한다>
최종 산출물 경로: <WS>/<NN>-<TEAM>.md
```

- 응답에 `REWORK <에이전트이름>: <피드백>` 이 있으면 그 팀원을 피드백과 함께 다시 호출하고
  (원래 과제 + "리더 피드백: ..."), 리더 검토를 한 번 더 한다. **팀원당 재작업은 1회까지.**
  두 번째 검토에서는 REWORK를 무시하고 리더에게 지금 있는 것으로 마무리하라고 한다.
- 에이전트(리더 포함) 응답을 받을 때마다 작업 공간 밖에 파일을 만들지 않았는지 본다. 만들었다면 `<WS>/<NN>-<TEAM>/<에이전트이름>-files/`로 옮기고(다시 만들 수 있는 빌드 캐시는 지운다) 다음 검토 프롬프트에 알린다.
- `DONE` 이면 리더가 `<WS>/<NN>-<TEAM>.md` 를 썼는지 확인한다. 없으면 리더에게 작성을 다시 요청한다.

## 에이전트가 오류로 끊기면

API 오류·사용량 한도 등으로 에이전트가 결과 없이 끝나면, 그 에이전트에게 SendMessage로
"끊겼다가 재개한다. 이어서 끝내라 — 지금까지 쓴 파일: <목록>"을 보내 같은 맥락으로 잇게 한다.
이어 갈 수 없으면 같은 프롬프트로 새로 호출한다. 이것은 재작업 1회에 세지 않는다.
다시 실패하면 그 자리에서 멈추고 CEO에게 알린다 — 같은 지시로 다시 실행하면 0단계부터 이어진다.
